# Roadmap Projection Model

## Purpose

Role-based roadmaps are projections from the Master Syllabus through the Capability Graph.

A roadmap is not the source of truth. It is a target-role-specific execution path.

## Strategy Anchor

- Product: Career Transformation Operating System for Engineers.
- Persona: 5-15 YOE Software, Senior, and Lead engineers targeting higher-seniority product/GCC/FAANG-level roles.
- First-customer outcome: help the founder/user progress toward Solution Architect, Staff-level, Engineering Manager, FAANG-level readiness, and a 70-80+ LPA outcome.
- MVP beta scope: one complete Senior/Lead Backend -> AWS Solution Architect / Staff-ready Backend path.
- Build sequence: project required capabilities from target role, order syllabus topics, assign proof tasks, then generate daily missions.
- Do not build yet: many shallow roadmaps or roadmaps detached from capability/readiness evidence.

## Projection Flow

```txt
Current State
  -> Target Role
  -> Required Capabilities
  -> Required Skills
  -> Syllabus Topics
  -> Ordered Tasks
  -> Proof of Competency
  -> Daily Missions
```

## Roadmap Structure

```txt
Target Role
  -> Capability
    -> Skill
      -> Topic
        -> Task
          -> Proof of Competency
```

## Projection Inputs

- Current role and level.
- Target role.
- Company target, such as product, GCC, or FAANG-level.
- Time budget.
- Deadline.
- Weak areas.
- Completed topics and tasks.
- Readiness scores.
- Required proof artifacts.

## Projection Outputs

- Ordered roadmap stages.
- Required topics.
- Optional/depth topics.
- Daily mission candidates.
- Blocking gaps.
- Proof tasks.
- Interview drills.
- Offer-readiness actions.

## Roadmap Types

MVP should prioritize:

- Founder beta path.
- Senior Backend Engineer path.
- AWS Solution Architect path.
- Staff-ready Backend Engineer path.

Other paths can exist as placeholders or partial projections, but should not distract from the first complete path.

## Completion Rules

Roadmap completion should require:

- Topic readiness above threshold.
- Capability readiness above threshold.
- Interview readiness for target role.
- Offer-readiness artifacts when the goal is job switch.
- Proof tasks reviewed or self-assessed against rubric.

## Non-Goals

- Static course sequence as the only roadmap.
- Same roadmap for every target role.
- Roadmaps detached from the Master Syllabus.
- Progress percentages that hide interview or offer gaps.

# Master Syllabus Model

## Purpose

The Master Syllabus is the canonical source of truth for EngineeringOS content.

Role roadmaps, courses, daily missions, topic pages, practice tasks, interview drills, and readiness scoring should project from the Master Syllabus instead of duplicating content.

## Strategy Anchor

- Product: Career Transformation Operating System for Engineers.
- Persona: 5-15 YOE engineers with limited time and high-seniority goals.
- First-customer outcome: move the founder/user toward Solution Architect, Staff-level, Engineering Manager, FAANG-level readiness, and a 70-80+ LPA product/GCC outcome.
- MVP beta scope: complete the highest-ROI syllabus for one beta path before expanding breadth.
- Build sequence: audit existing content, define canonical topic fields, map topics to capabilities, then fill beta path gaps.
- Do not build yet: raw content dumps, unreviewed AI content, or separate course content that forks the syllabus.

## Canonical Structure

```txt
Master Syllabus
  -> Domain
    -> Module
      -> Topic
        -> Concept
        -> Practice Task
        -> Interview Prompt
        -> Implementation Task
        -> Proof of Competency
        -> Source Reference
```

## Topic Requirements

Each topic should include:

- Stable ID and slug.
- Domain and module.
- Summary and why it matters.
- Prerequisites.
- Target roles served.
- Capability links.
- Knowledge content.
- Practice tasks.
- Interview prompts.
- Implementation tasks.
- Proof-of-competency rubric.
- Source references.
- Estimated time.
- Difficulty and seniority relevance.

## Canonical Scoring Dimensions

Topic completion is not binary. Each topic must support:

- Knowledge Score.
- Practice Score.
- Interview Score.
- Implementation Score.

These scores can roll up into capability readiness, but they should remain visible separately.

## Roadmap Projection Rule

Role roadmaps should reference syllabus topics and capabilities. They should not fork content into separate competing lesson structures.

## Content Quality Bar

High-ROI beta topics must include:

- Practical explanation.
- Real-world backend/product use case.
- Coding or design task when applicable.
- Interview prompts.
- Common mistakes.
- Completion criteria.
- Proof-of-competency artifact or assessment.

## MVP Content Strategy

One complete beta path is more valuable than broad shallow coverage.

Before expanding the syllabus, complete the highest-ROI topics for:

- DSA patterns.
- Backend engineering.
- HLD.
- LLD.
- AWS architecture.
- Staff/architect communication.
- Career assets.

## Non-Goals

- Raw imported notes without evaluation criteria.
- Course-first duplication.
- Huge topic lists with no proof tasks.
- AI-generated content accepted without review.

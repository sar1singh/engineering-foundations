Distributed Caching Strategies

Mastering cache invalidation in distributed systems

Cache invalidation is one of the hardest problems in computer science. In a globally distributed system, ensuring consistency across regional edge nodes requires careful orchestration. When a primary database updates a record, stale data lingering in caches can lead to critical consistency anomalies.

To mitigate this, modern architectures often employ a combination of time-to-live (TTL) expiration, pub/sub invalidation messaging, and write-through or write-behind caching patterns depending on the consistency requirements of the application.

The Thundering Herd Problem: Occurs when a highly concurrent cache key expires, and thousands of requests simultaneously miss the cache and hit the underlying database, potentially overwhelming it. Mitigate using jitter on TTLs or probabilistic early expiration.

Global CDN Topology

A typical global deployment places compute and cache layers at edge locations closest to the user. The edge nodes communicate back to regional hubs, which eventually funnel to a single authoritative origin database.

Implementation Example

Below is a naive implementation of a read-through cache wrapper using Redis in Go. Notice the explicit handling of cache misses and the application of a TTL to ensure eventual consistency.

func GetUserProfile(ctx context.Context, id string) (*Profile, error) {
    // 1. Attempt Cache Read
    val, err := rdb.Get(ctx, "user:"+id).Result()
    if err == nil {
        var p Profile
        json.Unmarshal([]byte(val), &p)
        return &p, nil
    }

    // 2. Cache Miss - Read Origin
    p, err := db.FindUser(id)
    if err != nil {
        return nil, err
    }

    // 3. Write-Through with TTL
    b, _ := json.Marshal(p)
    rdb.Set(ctx, "user:"+id, b, 5*time.Minute)

    return p, nil
}
